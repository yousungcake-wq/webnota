# 08. 모바일·태블릿 UX (`MB`)

AppFlowy `mobile/presentation/*`를 기준으로 합니다. 목표는 "Android 앱만큼 편하게"입니다.

## 1. 레이아웃 기준

| 구분 | 조건 | 레이아웃 |
|---|---|---|
| 폰 | 너비 < 768px | 하단 탭 + 전체 화면 스택 |
| 태블릿 세로 | 768~1023px, 터치 | 오버레이 사이드바 드로어 + 본문 |
| 태블릿 가로 / 데스크탑 | ≥ 1024px | 고정 사이드바 + 본문 |

입력 방식(`pointer: coarse`)과 화면 크기는 따로 판단합니다. 터치 태블릿은 넓은 레이아웃 + 터치 컨트롤(키보드 도구 모음, 큰 터치 영역)입니다.

## 3. 상호작용 규칙

| ID | 규칙 |
|---|---|
| MB-10 | 모든 메뉴는 하단 시트 ✅. 시트를 열면 키보드를 닫음 ✅. 아래로 끌어서 닫기, 높이 단계(절반/전체) |
| MB-11 | 터치 영역 최소 44×44px |

| MB-13 | 스와이프: 트리 항목 왼쪽 스와이프 → 즐겨찾기/삭제 버튼 (AppFlowy `page_item`), 페이지 화면 왼쪽 가장자리 스와이프 → 뒤로 (iOS는 브라우저 기본 동작 사용, 충돌 방지) |
| MB-14 | Android 하드웨어 뒤로 버튼: 시트/모달 닫기 → 화면 뒤로 → 홈에서 앱 종료. 시트를 열 때 history 항목을 추가하는 방식으로 구현 |
| MB-15 | 당겨서 새로 고침 (홈) → 즉시 동기화 (P1) |
| MB-16 | 햅틱 (`navigator.vibrate`, Android만): 드래그 시작, 체크박스 토글 (설정에서 끄기) |
| MB-17 | 안전 영역: `env(safe-area-inset-*)` ✅ (노치, 홈 인디케이터) |
| MB-18 | 화면 회전, 분할 화면, 폴더블 대응 (레이아웃 재계산, 상태 유지) |

## 7. 실기기 검증 매트릭스

| 기기 | 브라우저 | 필수 |
|---|---|---|
| Android 중간 사양 (예: Galaxy A 시리즈) | Chrome, Samsung Internet | ✅ |
| Android 고사양 | Chrome | ✅ |
| iPhone (iOS 17+) | Safari, 홈 화면 PWA | ✅ |
| iPad | Safari (가로·세로, 외장 키보드) | ✅ |
| Windows / macOS | Chrome, Edge, Safari, Firefox | ✅ |

자동화 대체: Playwright 기기 에뮬레이션(Pixel 7, iPhone 14, iPad), WebKit 엔진 실행(Playwright webkit), CDP IME 테스트. 단, IME와 키보드 동작은 에뮬레이션으로 완전히 검증할 수 없으므로 사용자 실기기 확인을 마일스톤 완료 조건에 넣습니다.
