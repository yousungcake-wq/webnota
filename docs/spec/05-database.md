# 05. 데이터베이스 (`DB`)

AppFlowy `plugins/database/{grid,board,calendar,tab_bar,widgets}`를 기준으로 합니다.

## 1. 개념

- **데이터베이스**: 필드 + 행. 저장은 `db/<id>` (스키마, 뷰)와 `dbr/<id>/<shard>` (행)입니다 ([02-data-model.md](02-data-model.md) §4).
- **뷰**: 같은 데이터를 보는 방식입니다 (Grid, Board, Calendar). 뷰마다 필터, 정렬, 그룹, 필드 표시 설정이 따로 있습니다.
- **탭 바**: 한 데이터베이스의 여러 뷰를 상단 탭으로 전환합니다 (AppFlowy `tab_bar`). 탭 추가 = 새 뷰(레이아웃 선택), 이름 바꾸기, 복제, 삭제, 순서 변경.
- **연결된 뷰**: 사이드바나 문서 안에서 기존 데이터베이스를 새 뷰로 참조합니다 ("기존 데이터베이스 연결").
- **행 페이지**: 행을 열면 속성 목록 + 문서 본문이 나옵니다. 데스크탑은 가운데 모달(전체 화면 전환 가능), 폰은 전체 화면입니다.

## 2. 쿼리 엔진 (`core/model/database/query.ts`)

UI와 분리된 순수 함수입니다. 모든 뷰가 공유하고, 단위 테스트를 둡니다.

```ts
function runQuery(input: {
  fields: FieldMap; rows: RowSnapshot[]; view: ViewSettings; now: number; me: string
}): {
  rowIds: string[]                 // 필터 + 정렬 적용 결과
  groups?: { key: string; rowIds: string[] }[]   // Board
  calcs?: Record<fieldId, CalcResult>
}
```

- **증분 갱신**: 행 변경 이벤트(Yjs observeDeep의 변경 키)를 받으면 해당 행만 다시 평가합니다. 필터 일치 여부를 다시 계산하고, 정렬 위치는 이진 탐색으로 삽입합니다. 전체 재계산은 설정이 바뀔 때만 합니다.
- **5,000행 이상**이면 쿼리를 `query.worker.ts`로 넘깁니다. 행 스냅샷은 구조적 복제 대신 변경분만 전송합니다.
- 구현 (M4-04): `createLiveQuery`(core, 증분) ← `observeRows`(샤드 `observeDeep`의 행 id) / `observeSchema`(schema 문서 트랜잭션마다 전체 재계산). 화면은 `features/database/session.ts`의 `openDbSession`(문서 retain + 관찰 + 실행기)을 `useDbSession`으로 구독합니다. 워커 여부는 세션을 열 때 행 수로 정합니다(`WORKER_THRESHOLD = 5000`, 이후 커져도 바꾸지 않음). 워커 메시지는 `init`(전체 행 1회) → `apply`(바뀐 행만) / `query`(설정), 응답은 마지막 요청 번호만 반영.
- 정렬 비교는 `Intl.Collator('ko', { numeric: true })`를 씁니다 (한글, 숫자 자연 정렬. 한글이 라틴 문자보다 앞).
- 구현 규칙 (M4-03, `core/model/database/query.ts`): `compileQuery`가 행 판정(`matches`)과 비교 함수(`compare`: 정렬 조건 → 수동 순서 `(order, id)`)를 만들고 `runQuery`가 필터 → 정렬 → 계산을 합니다. 값이 필요한 조건은 값이 비어 있으면 적용하지 않습니다(조건을 막 만든 상태). 텍스트 비교는 대소문자 무시. 숫자 조건은 빈 셀이면 `≠`만 참. 삭제된 선택 옵션은 빈 값. select 정렬은 이름이 아니라 옵션 순서(AppFlowy). 체크박스 정렬은 해제 → 체크(빈 값 취급 안 함). "이번 주"는 `weekStart`(기본 일요일), "지난 7일"은 오늘 포함 7일. 계산의 백분율은 0~100, 숫자가 없으면 `null`(합계는 0), 날짜 필드는 최소·최대·범위(ms). 행 검색은 `cellText`(옵션 이름·날짜 등 평문) 기준.

| 타입 | 셀 표시 | 셀 편집 (데스크탑 / 폰) |

| date | 서식 날짜, 범위 `시작 → 끝` | 달력 팝오버: 시간 포함, 종료일, 날짜·시간 형식, 지우기, 리마인더(M10) / 시트 |
| checkbox | 체크박스 | 탭 토글 |
| checklist | 진행률 바 `3/5` | 항목 추가, 체크, 이름 바꾸기, 삭제, 순서 변경, "완료 숨기기" |

| createdTime / updatedTime | 시각 | 읽기 전용 |
| relation | 연결된 행 칩 | 대상 DB 행 검색 선택기, 칩 클릭 → 행 페이지 |
| rollup | 계산 결과 | 읽기 전용 |
| media | 썸네일 / 파일 아이콘 | 업로드, 미리보기, 삭제, 순서 변경 |
| time | `1h 30m` | 분 입력 / 스톱워치(P2) |

구현 (M4-05): 서식·입력 해석은 `core/model/database/format.ts`(순수, 로캘은 앱 언어 `ko-KR`/`en-US`). 숫자: 천 단위 구분(`separator`, 기본 켬), 소수 자릿수(`decimals`, 없으면 그대로), 백분율(저장 0.25 → `25%`, 입력 `25`·`25%` → 0.25), 통화 KRW·USD·EUR·JPY·GBP·CNY. 입력은 구분자·통화 기호·`원`을 무시하고, 숫자가 아니면 기존 값을 유지합니다. 소요 시간: `1h 30m`, `90`(분), `1:30`, `1.5h`, `2시간 10분` → 분. URL: 도메인만 쓰면 `https://`를 붙이고, 열기 버튼은 http(s)·mailto만. 편집: 셀을 고른 상태에서 다시 누르거나 Enter, 또는 바로 입력(내용 교체). Enter 저장 후 아래로, Tab 오른쪽, Esc 취소, 텍스트는 Shift+Enter 줄 바꿈. Delete/Backspace는 셀 비우기, Space는 체크박스 토글. 만든·수정한 시각은 편집 불가.

### 3.3 select 옵션 색상

AppFlowy 팔레트 10색(Purple, Pink, Light Pink, Orange, Yellow, Lime, Green, Aqua, Blue, Gray)을 씁니다. 라이트·다크 대비를 모두 만족하도록 토큰으로 정의합니다.

구현 (M4-06): 옵션 목록은 `options.choices` 한 값(LWW)으로 통째로 씁니다(`core/model/database/choices.ts`: 추가 시 같은 이름이면 기존 옵션, 색은 팔레트 순환). 옵션을 지우면 그 옵션을 가리키던 셀은 빈 값으로 읽힙니다(셀은 그대로 둠). 색 토큰은 `--sel-<color>`(배경, 글자는 `--text`, 라이트·다크). 날짜 형식 `dateFormat`: friendly(로캘 기본)·iso·us·eu, `timeFormat`: 24(기본)·12. 날짜 입력 해석 `parseDate`: `YYYY-MM-DD`, `YYYY.MM.DD`, `YYYY/MM/DD`, `2026. 11. 7.`, 선택적 `HH:mm`. 종료일을 켜면 달력 클릭이 시작·끝을 번갈아 고르고, 끝이 시작보다 앞이면 바꿉니다. 시간 포함을 켜면 09:00으로 시작. 체크리스트의 "완료 숨기기"는 화면 상태(저장 안 함). 편집기는 데스크탑 팝오버, 폰 하단 시트(`Overlay`).

### 3.4 타입 변환 규칙

| 원래 → 새 타입 | 변환 |
|---|---|
| 모든 타입 → text | 표시 문자열 |
| text → number | `parseFloat` (실패 시 null) |
| text → select/multi | 값을 옵션으로 생성 (쉼표 분리는 multi만) |
| select ↔ multiSelect | 단일 ↔ 배열 (multi → select는 첫 값) |
| text/number → date | 날짜 파싱 (ISO, `YYYY.MM.DD`, `YYYY-MM-DD`) |
| checkbox ↔ text | "true"/"yes"/"1"/"✓" ↔ boolean |
| 그 외 | 값 비움 (변환 전 확인 대화상자: "N개 셀의 값이 사라집니다") |

원본 값은 변환 후 30초 동안 실행 취소할 수 있습니다. 구현 (M4-07, `core/model/database/convert.ts`): Y.UndoManager는 문서 하나만 다룰 수 있는데 DB는 schema + 샤드 8개라, `convertField`가 바꾼 셀의 이전 값을 기억했다가 되돌리는 `undo`를 돌려줍니다 (변환 뒤에 다시 고친 셀은 건드리지 않음). 추가 규칙: number ↔ time은 값 유지(분), → URL은 → 텍스트와 같음(텍스트는 그대로), 체크 해제 → 텍스트는 빈 값, 만든·수정한 시각 → 날짜는 행 시각(시간 포함), 만든·수정한 시각으로 바꾸면 저장된 셀은 지웁니다. select ↔ multi는 쓰지 않는 옵션도 유지. media 셀은 `{fileId, name, mime, size}[]`, 업로드는 `core/files/ingest`(지연), 파일 참조는 `core/files/refs.ts`의 `fileRefsInRows`(셀의 fileId 항목 + 행 아이콘·커버, 필드 타입과 무관하게)로 저장소 정리에서 보존.

### 4.1 정렬
- 여러 조건을 순서대로 적용합니다 (드래그로 우선순위 변경). 오름차순/내림차순.
- 빈 값은 항상 마지막입니다.

### 4.2 필터 조건

| 타입 | 조건 |
|---|---|
| text, url | 포함, 포함 안 함, 같음, 같지 않음, 시작, 끝, 비어 있음, 비어 있지 않음 |
| number, time | `=`, `≠`, `>`, `≥`, `<`, `≤`, 비어 있음, 비어 있지 않음 |
| select | 다음 중 하나, 다음 중 아무것도 아님, 비어 있음, 비어 있지 않음 |
| multiSelect | 모두 포함, 하나라도 포함, 포함 안 함, 비어 있음, 비어 있지 않음 |
| date, createdTime, updatedTime | 이전, 이후, 같은 날, 범위, 오늘·이번 주·이번 달·지난 7일 (상대), 비어 있음 |
| checkbox | 체크됨, 체크 안 됨 |
| checklist | 모두 완료, 미완료 |
| relation | 포함, 비어 있음 |

- AND/OR 그룹을 지원하고 중첩은 2단계까지입니다 (AppFlowy 고급 필터).
- 필터가 있는 뷰에서 새 행을 추가하면, 가능한 경우 필터 조건 값을 미리 채웁니다 (그래야 바로 사라지지 않음).

## 8. 인라인·연결된 데이터베이스 (`DB-L`, M5)

- 문서 블록 `database`: 새로 만들기(Grid/Board/Calendar) 또는 기존 DB 연결을 선택합니다.
- 인라인 뷰는 높이가 제한되고(기본 400px, 조절 가능) "전체 페이지로 열기" 버튼이 있습니다.
- 사이드바의 DB 뷰 아래에 다른 뷰를 연결할 수 있습니다.

## 9. 가져오기·내보내기 (`DB-IO`, M6)

- CSV 가져오기: 첫 행 = 헤더, 타입 자동 추론(숫자, 날짜, 체크박스, 선택 — 고유 값 20개 이하), 미리보기 후 확인. 워커에서 파싱합니다.
- CSV 내보내기: 현재 뷰의 필터·정렬·표시 필드 기준, 또는 전체.

## 10. 관계와 롤업 (`DB-X`, M6)

- 관계 필드: 같은 DB 또는 다른 DB를 대상으로 합니다. 양방향 옵션을 켜면 상대 DB에 짝 필드를 만들고, 양쪽에 같은 트랜잭션 의미로 기록합니다 (두 Y.Doc이므로 실패 시 보정 로직 필요 — 동기화 후 불일치를 검사하고 복구).
- 롤업 (P2): 관계 필드 → 대상 필드 → 함수(count, sum, avg, min, max, 고유값 목록, % 체크 등).

## 11. 성능 요구 사항

| 시나리오 | 목표 |
|---|---|
| 10,000행 × 20필드 Grid 열기 (IndexedDB) | < 800ms |
| 스크롤 | 60fps (중간 사양 Android 기준 50fps 이상) |
| 셀 편집 반영 | < 16ms |
| 필터 변경 (10,000행) | < 100ms (워커) |
| Board 1,000카드 드래그 | 끊김 없음 (열 단위 가상화) |

## 12. 테스트

- 쿼리 엔진: 필터 조건 × 필드 타입 전수 테스트, 정렬 안정성, 그룹 키, 계산 값, 증분 갱신과 전체 재계산 결과 일치 (속성 기반 테스트, fast-check).
- 타입 변환: 표 §3.4 전수.
- e2e: Grid 키보드 탐색, Board 드래그(마우스·터치), Calendar 드래그, CSV 왕복.
